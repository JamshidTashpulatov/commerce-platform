# Catalog administration (development)
Administrators create draft products, assign a text category, description and optional approved HTTPS image URL, and create separately priced color/storage/SKU variants. A new variant starts at zero inventory. Editing uses revisions; new records use request keys. Publishing requires an active variant. A published product's last active variant cannot be disabled until the product is unpublished. Past order item prices are snapshots and are not updated by catalog edits.
The server-backed public catalog is available at /catalog with search, category filtering and variant selection. Only published products with active variants are returned; inventory is represented by availability, not exact quantity. The existing demo storefront and its simulated checkout remain separate. Public catalog ordering, cart/compare integration, real customer Telegram authentication, category management, file upload, CDN configuration, full pagination and visual QA remain pending. Images are URLs from an explicitly configured allowlist; no server-side fetching or uploads. Do not publish private media. Catalog mutation is disabled by default.
