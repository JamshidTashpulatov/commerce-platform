# Catalog image uploads (development)
Catalog images follow the standard in [CATALOG-IMAGES.md](CATALOG-IMAGES.md). The normalise-and-store step lives in `lib/server/catalog-media-store.ts`, shared by the upload route and the catalog image scripts.
Admins may upload a product cover, an image for an option value, or an override for a SKU from their device. A raw authenticated same-origin upload accepts JPEG, PNG and static WebP up to 3 MiB, decodes with a 16-million-pixel limit, applies orientation, resizes to fit 1600px and re-encodes to WebP without original metadata. Output is capped at 1 MiB. SVG, animated images, mismatched formats and corrupt inputs are rejected. The store-scoped PostgreSQL bytea table deduplicates normalized images by SHA-256 and enforces a 2000-image / 256 MiB per-store application quota. There is no file-system dependency or external object storage credential for this initial implementation.
The image is only publicly readable when referenced by a published product with an active variant; privileged admins can preview drafts. Each media request is store-scoped and no-store. A local media reference must exist in that store before catalog writes. Existing allowlisted external URLs remain supported by the backend. Removing an image from the form detaches the reference when saved; it does not physically delete the stored image. Orphan cleanup, gallery/multiple photos, drag-and-drop, CDN/object storage migration and production traffic/load testing remain pending. Uploads are controlled by CATALOG_ADMIN_ENABLED. No deployment or real media upload has been performed.
