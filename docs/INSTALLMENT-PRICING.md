# Cost-based installment pricing
The authorized staff member enters acquisition cost, agreed initial payment and term. The server computes the minimum initial payment using the configured basis-point rate (rounded upward to whole UZS). A larger initial payment is allowed, below cost. The flat monthly markup is based on original financed cost (cost minus initial payment), not the declining debt. Total markup is rounded once to whole UZS, and schedule rounding distributes the remainder across earliest months.
The server persists a pricing snapshot (cost, principal, markup, duration and both rates); the client cannot supply an arbitrary total or rates for installments. Activation uses the saved term. Legacy manually priced drafts cannot activate without a new pricing snapshot; existing active contracts are not recalculated.
Configure INSTALLMENT_MIN_INITIAL_BPS and INSTALLMENT_MONTHLY_MARKUP_BPS privately using approved rates; public CI uses illustrative fixture values only. Real activation remains disabled pending production review. This is a manual recording application, not a payment gateway. Funding allocation, cost verification against inventory accounting, and correction of legacy drafts with recorded receipts remain pending.
