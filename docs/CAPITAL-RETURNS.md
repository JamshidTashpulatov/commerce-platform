# Principal return ledger (development)
An administrator explicitly allocates a recorded, unreversed initial receipt to the investors who funded the sold order. Full acquisition funding is required. The allocations must sum to the receipt and must not exceed each participant's outstanding capital. No profit is recognized. The server uses a transaction, order lock, sorted investor membership locks, and receipt-linked unique records. Repeated identical requests are idempotent. All reusable balance and withdrawal checks use original allocations less posted principal returns.
Automatic proportional allocation is not assumed. Initial returns currently require manual admin confirmation; monthly principal and profit are posted automatically under the rules in PROFIT-ALLOCATION.md. Posted initial receipts cannot be reversed through the ordinary receipt workflow because their released funds may already be reused. A safe corrective ledger workflow is pending. No real transactions or money transfers occur. The feature is disabled by default.
